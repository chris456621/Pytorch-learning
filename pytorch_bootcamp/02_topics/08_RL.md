## §1 RL 跟監督式學習的根本差異

| | 監督式 | 強化式 |
|---|---|---|
| 資料 | 固定資料集 | ★ **agent 自己產生**（會隨策略改變） |
| 訊號 | 每筆都有正確答案 | ★ 只有 reward，且常常**延遲**又**稀疏** |
| 目標 | 最小化預測誤差 | 最大化**累積**回報 |
| i.i.d. 假設 | 成立 | ★ **不成立**（連續狀態高度相關） |

> 這三個差異解釋了 RL 為何難：**資料分布會隨訓練改變（非平穩）**，
> 而且你不知道「哪一步做對了」（credit assignment problem）。

## §2 MDP 與核心概念

**馬可夫決策過程** `(S, A, P, R, gamma)`：狀態、動作、轉移機率、獎勵、折扣因子。

**回報（return）**：`G_t = r_t + gamma*r_{t+1} + gamma^2*r_{t+2} + ...`

**價值函數：**

```
V(s)   = E[ G_t | s_t = s ]                 狀態價值
Q(s,a) = E[ G_t | s_t = s, a_t = a ]        動作價值
A(s,a) = Q(s,a) − V(s)                      優勢函數（做這動作比平均好多少）
```

**Bellman 方程：**

```
Q(s,a)  = E[ r + gamma * Q(s', a') ]                   策略評估
Q*(s,a) = E[ r + gamma * max_{a'} Q*(s', a') ]         ★ Bellman 最優方程
```

> ★ **Q-learning 就是把 Bellman 最優方程當成訓練目標**：
> 讓 `Q(s,a)` 去逼近 `r + gamma * max_a' Q(s',a')`。

---

## §3 兩大流派

| | Value-based | Policy-based |
|---|---|---|
| 學什麼 | `Q(s,a)`，策略是 `argmax Q` | 直接學策略 |
| 動作空間 | 只能離散 | ★ 連續也可以 |
| 探索 | epsilon-greedy | 策略本身有隨機性 |
| 樣本效率 | ★ 高（off-policy 可重用資料） | 低（多半 on-policy） |
| 穩定性 | 較差 | ★ 較好 |
| 代表 | DQN | REINFORCE, PPO |

兩者結合就是 **Actor-Critic**（A2C, PPO, SAC, DDPG）。

## §4 DQN ★

### 4.1 三個關鍵設計

**問題**：直接用神經網路擬合 Q 會發散。原因：
1. 連續樣本高度相關（違反 i.i.d.）
2. 目標值 `r + gamma*max Q(s')` 用同一個網路 → 「追著自己的尾巴跑」

| 技術 | 解決什麼 |
|---|---|
| **Replay Buffer** | ★ 打散樣本相關性，且能重複使用資料 |
| **Target Network** | ★ 讓目標值在一段時間內固定，避免震盪發散 |
| epsilon-greedy | 探索 vs 利用的平衡 |

### 4.2 實作

```python
import random
from collections import deque, namedtuple
import torch
import torch.nn as nn
import torch.nn.functional as F

Transition = namedtuple("Transition", "s a r s2 done")

class ReplayBuffer:
    def __init__(self, capacity=50_000):
        self.buf = deque(maxlen=capacity)
    def push(self, *args):
        self.buf.append(Transition(*args))
    def sample(self, batch_size):
        batch = random.sample(self.buf, batch_size)
        b = Transition(*zip(*batch))                    # ★ zip(*) 轉置的漂亮用法
        return (torch.stack(b.s), torch.tensor(b.a),
                torch.tensor(b.r, dtype=torch.float32),
                torch.stack(b.s2), torch.tensor(b.done, dtype=torch.float32))
    def __len__(self):
        return len(self.buf)


class QNet(nn.Module):
    def __init__(self, obs_dim, n_actions, hidden=128):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, n_actions),               # ★ 輸出每個動作的 Q 值
        )
    def forward(self, s):
        return self.net(s)


def dqn_update(q_net, target_net, buffer, optimizer,
               batch_size=64, gamma=0.99, double=True):
    if len(buffer) < batch_size:
        return None
    s, a, r, s2, done = buffer.sample(batch_size)

    # 當前 Q(s,a)  ★ 用 gather 取出實際採取的動作
    q_sa = q_net(s).gather(1, a[:, None]).squeeze(1)          # (B,)

    with torch.no_grad():                                     # ★ target 不能有梯度
        if double:
            # Double DQN：online net 選動作、target net 估值（減少高估偏差）
            a2 = q_net(s2).argmax(1, keepdim=True)
            q_next = target_net(s2).gather(1, a2).squeeze(1)
        else:
            q_next = target_net(s2).max(1).values
        target = r + gamma * q_next * (1 - done)              # ★ done 時沒有未來獎勵

    loss = F.smooth_l1_loss(q_sa, target)                     # ★ Huber 比 MSE 穩
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    nn.utils.clip_grad_norm_(q_net.parameters(), 10.0)
    optimizer.step()
    return loss.item()
```

**主迴圈：**

### 逐行拆解 `dqn_update`

```python
sb, ab, rb, s2b, db = buffer.sample(batch_size, device)
```
一次解包五個東西：狀態、動作、獎勵、下一個狀態、是否結束。形狀都是 `(B, ...)`。

```python
q_sa = q_net(sb).gather(1, ab[:, None]).squeeze(1)
```
- `q_net(sb)` → `(B, n_actions)`，每個動作都有一個 Q 值
- 但我們只要「**當初實際做的那個動作**」的 Q 值
- `ab[:, None]` 把 `(B,)` 變成 `(B,1)` —— `gather` 要求 index 的維度數跟來源相同
- `gather(1, idx)` 沿第 1 維（動作維）各挑一個 → `(B,1)`
- `.squeeze(1)` 壓回 `(B,)`

> 💡 等價的好讀寫法：`q_net(sb)[torch.arange(B), ab]`。
> 兩者差異見 `01_syntax/15_同性質語法差異比較.md` §17。

```python
with torch.no_grad():
    q_next = target_net(s2b).max(1).values
```
- **`no_grad` 不能省**：target 是「當作事實的目標值」，不是要被優化的對象。
  沒包的話梯度會流進 target_net，訓練直接發散
- `.max(1)` 回傳 `(values, indices)` 兩個東西，`.values` 取出值的那個
  （這跟 NumPy 不同，NumPy 的 `max` 只回傳值）

```python
target = rb + gamma * q_next * (1 - db)
```
- Bellman 方程：現在的價值 = 立即獎勵 + 折扣後的未來最好價值
- **`(1 - db)` 是最容易漏掉的一項**：`db` 是 1 代表這一局結束了，
  結束之後沒有未來，未來那一項必須歸零。
  漏掉的話模型會以為「死掉之後還能一直拿分」，Q 值就無限膨脹

```python
loss = F.smooth_l1_loss(q_sa, target)
```
- Huber loss：誤差小的時候像 MSE（平滑好優化），大的時候像 MAE（不被離群值帶偏）
- RL 的 target 本來就很吵，用純 MSE 容易被少數極端值毀掉

> 🔥 **三個最常見的 DQN bug**：
> 1. **target 忘記 `no_grad`** → 梯度流進 target network，訓練發散
> 2. **忘記 `(1 - done)`** → 終止狀態還在算未來獎勵，Q 值無限膨脹
> 3. **target network 更新太頻繁** → 等於沒有 target network

### 4.3 DQN 的改良（Rainbow 的組成）

| 改良 | 解決 |
|---|---|
| Double DQN | `max` 造成的 Q 值高估 |
| Dueling DQN | 把 Q 拆成 `V(s) + A(s,a)`，V 更容易學 |
| Prioritized Replay | 重要的 transition 多抽幾次 |
| N-step return | 加快獎勵傳播 |
| Noisy Net | 用參數化雜訊取代 epsilon-greedy |

## §5 Policy Gradient / REINFORCE ★

### 5.1 策略梯度定理

```
grad J(theta) = E[ grad log pi(a|s) * G_t ]
```

**直覺**：如果某個動作帶來高回報，就提高它的機率；反之降低。

### 5.2 為何 loss 寫成 `-log_prob * G`

PyTorch 的優化器是**最小化** loss，但我們要**最大化** `J(theta)`。
所以定義 `loss = -log pi(a|s) * G`，`loss.backward()` 得到的梯度
正好是 `-grad J`，`optimizer.step()` 就是沿著 `+grad J` 走。

> ★ 這是 `07_autograd.md` 觀念的直接應用：
> **loss 不一定要是「誤差」，它可以是任何你想最小化的量。**

```python
from torch.distributions import Categorical

class PolicyNet(nn.Module):
    def __init__(self, obs_dim, n_actions, hidden=128):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, n_actions),          # ★ 輸出 logits，不加 softmax
        )
    def forward(self, s):
        return self.net(s)


def select_action(policy, s):
    dist = Categorical(logits=policy(s[None]))     # ★ 直接吃 logits，數值穩定
    a = dist.sample()
    return a.item(), dist.log_prob(a)              # ★ log_prob 要留在計算圖上！


def compute_returns(rewards, gamma=0.99):
    """從後往前算折扣回報。"""
    G, out = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        out.append(G)
    return list(reversed(out))


def reinforce_update(optimizer, log_probs, rewards, gamma=0.99):
    returns = torch.tensor(compute_returns(rewards, gamma))
    # ★ baseline：減平均除標準差，大幅降低梯度變異數
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)

    loss = -(torch.stack(log_probs) * returns).sum()     # ★★ 負號在這裡
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()
    return loss.item()
```

### 逐行拆解 `reinforce_update`

```python
returns = torch.tensor(compute_returns(rewards, gamma))
returns = (returns - returns.mean()) / (returns.std() + 1e-8)
loss = -(torch.stack(log_probs) * returns).sum()
```

**第 2 行（baseline）**
- 減平均：把「比平均好的動作」變正、「比平均差的」變負 →
  只加強真正好的，而不是「凡是拿到正分的都加強」
- 除標準差：把尺度標準化，讓 lr 不用隨任務調整
- `+ 1e-8` 防止除以 0（整局回報都一樣時 std 會是 0）
- **數學上這不改變梯度的期望值，只降低變異數** —— 免費的穩定性

**第 3 行（三個要素）**
- `torch.stack(log_probs)` 把一個「list of 純量 tensor」疊成一個 `(T,)` 的 tensor。
  ★ 用 `stack` 不是 `cat`，因為每個元素是純量（0 維），需要新增一維
- `* returns` 逐元素相乘：每一步的 log 機率乘上那一步之後的總回報
- **最前面的負號**：策略梯度要「**最大化**」期望回報，
  但 PyTorch 的優化器只會「最小化」loss，所以取負

> ★ 這是理解 autograd 的關鍵一課：**loss 不一定是「誤差」**，
> 它可以是任何你想最小化的量。這裡的 loss 值本身沒有物理意義，
> 有意義的只有它的梯度方向。

> 🔥 **REINFORCE 最常見的 bug**：
> 把 `log_prob` 存成 `.item()` 或 `.detach()` → 梯度斷掉，模型完全不學，
> 而且**不會報錯**。`log_probs` 必須是還在計算圖上的 tensor。

### 5.3 Baseline 與變異數

REINFORCE 的梯度變異數極大（同樣的動作，因為後面運氣不同，回報差很多）。

**解法**：減掉一個 baseline，不改變期望但大幅降低變異數：

```
grad J = E[ grad log pi(a|s) * (G_t − b(s)) ]
```

- 最簡單：`b` = 這個 batch 的平均回報（上面的 normalize）
- 更好：`b(s) = V(s)`，用一個網路學 → 這就是 **Actor-Critic**

## §6 Actor-Critic 與 PPO

```
Actor  pi(a|s)：決定做什麼
Critic V(s)   ：評估這個狀態好不好

Advantage:  A = r + gamma*V(s') − V(s)      （TD error，比 G_t 變異數小很多）
Actor loss:  −log pi(a|s) * A.detach()      ★ A 要 detach
Critic loss: (V(s) − target)^2
```

```python
def a2c_update(actor, critic, opt, s, a, r, s2, done, gamma=0.99):
    v = critic(s).squeeze(-1)
    with torch.no_grad():
        target = r + gamma * critic(s2).squeeze(-1) * (1 - done)
    adv = (target - v).detach()                       # ★ detach，不讓 critic 梯度混進 actor

    dist = Categorical(logits=actor(s))
    actor_loss = -(dist.log_prob(a) * adv).mean()
    critic_loss = F.mse_loss(v, target)
    entropy = dist.entropy().mean()                   # ★ 熵獎勵，鼓勵探索

    loss = actor_loss + 0.5 * critic_loss - 0.01 * entropy
    opt.zero_grad(); loss.backward(); opt.step()
```

### PPO（目前最常用的演算法）

**核心問題**：策略更新太大會崩潰。PPO 用 clipped objective 限制更新幅度：

```
ratio = pi_new(a|s) / pi_old(a|s)
L = min( ratio * A ,  clip(ratio, 1−eps, 1+eps) * A )       eps 通常 0.2
```

```python
ratio = (new_log_prob - old_log_prob.detach()).exp()
surr1 = ratio * adv
surr2 = torch.clamp(ratio, 1 - 0.2, 1 + 0.2) * adv
actor_loss = -torch.min(surr1, surr2).mean()
```

> ★ PPO 讓「同一批資料可以重複更新好幾次」而不會崩潰，
> 大幅提升樣本效率。這是它成為業界標準的原因。

## §7 RL 除錯清單（RL 比其他領域難 debug 十倍）

```
[ ] 1.  先在最簡單的環境驗證（例如只有 2 個狀態的玩具問題）
[ ] 2.  reward 的量級合理嗎？太大要正規化
[ ] 3.  target 有沒有 no_grad？
[ ] 4.  終止狀態有沒有乘 (1 - done)？
[ ] 5.  log_prob 有沒有不小心 detach 掉？
[ ] 6.  探索夠不夠？印出 epsilon 或 policy entropy
[ ] 7.  replay buffer 夠大嗎？開始訓練前有先填一些嗎？
[ ] 8.  Q 值有沒有無限膨脹？印出 q_sa.mean()
[ ] 9.  ★ 跑 5 個 seed —— RL 的 seed 變異極大，單次結果毫無意義
[ ] 10. 畫「每個 episode 的總 reward」曲線，不要只看 loss
```

> 🔥 **RL 的 loss 下降不代表學得好。** 一定要看 **episode return 曲線**。

## §8 RL 用在金融（給你的參考，但先看警告）

**可以做**：把交易當成 MDP —— 狀態是技術指標視窗，動作是買/賣/持有，
reward 是報酬率（要扣手續費和滑價）。

> ⚠️ **但要非常小心**：
> 1. 金融市場**不是 MDP**（非平穩、有其他參與者、狀態不完全可觀測）
> 2. reward 極度雜訊，訊噪比遠低於遊戲環境
> 3. 回測績效跟實盤差距巨大（滑價、手續費、流動性、生存者偏差）
> 4. **學術上這方向已經很多人做，但真正能穩定獲利的論文極少**
>
> 建議：**當成學習 RL 的練習題可以，但不要對績效有期待**，
> 更不要拿真錢去跑。你的 W25+ 研究專案，SSL 或壓縮的方向會踏實得多。
