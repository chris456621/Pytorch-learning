## 目錄

|---|---|---|
| 1 | `view` / `reshape` / `permute` / `transpose` | 不確定就用 `reshape` |
| 2 | `cat` / `stack` | `stack` 一定多一維 |

| 7 | 四種「不算梯度」的寫法 | 驗證用 `no_grad`，切單條路用 `detach` |
| 8 | `clone` / `detach` | 完全獨立要 `clone().detach()` |
| 9 | `nn.ReLU` / `F.relu` | 有參數用 `nn.`，沒參數兩者皆可 |
| 10 | 三種裝層的容器 | **絕對不能用 Python list** |
| 11 | 四種 Normalization | CNN 大 batch 用 BN，Transformer 用 LN |
| 12 | 四種分類 loss | 多類用 `CrossEntropyLoss`，二類用 `BCEWithLogits` |
| 13 | `Adam` / `AdamW` / `SGD` | 一般用 `AdamW` |
| 14 | `reduction` 的三種值 | 想加權時用 `none` |
| 15 | `model.eval()` / `torch.no_grad()` | **兩個都要，管的事不同** |
| 16 | `max` / `amax` / `argmax` / `topk` | 要值又要索引用 `max` |
| 17 | `gather` / `index_select` / 花式索引 | 每列取不同索引用 `gather` |
| 18 | pandas `loc` / `iloc` / `[]` / `at` | 條件篩選用 `loc` |
| 19 | pandas `apply` / `map` / 向量化 | 能向量化就不要 apply |
| 20 | pandas `merge` / `join` / `concat` | 像 SQL JOIN 用 `merge` |
| 21 | groupby 的 `agg` / `transform` / `apply` | 要當新欄位用 `transform` |
| 22 | NumPy copy vs view | 切片是 view，花式索引是 copy |
| 23 | `axis` vs `dim`、`keepdims` vs `keepdim` | 意思一樣，名字不同 |
| 24 | `*` / `@` / `matmul` / `einsum` | 矩陣乘法用 `@` |
| 25 | 三種存模型的方式 | **一律存 `state_dict`** |
| 26 | `float16` / `bfloat16` / `float32` | 你的 4060 用 `bfloat16` |
| 27 | DataLoader 的參數組合 | 訓練 True/True，驗證 False/False |

## 1. view vs reshape vs permute vs transpose

| | 做什麼 | 會複製記憶體嗎 | 需要連續嗎 | 維度數會變嗎 |
|---|---|---|---|---|
| `view(2,3)` | 改形狀 | ❌ 絕不 | ✅ **需要** | 可能 |
| `reshape(2,3)` | 改形狀 | 需要時會 | ❌ 不需要 | 可能 |
| `permute(0,2,1)` | 換維度**順序** | ❌ 不會 | ❌ 不需要 | ❌ 不變 |
| `transpose(1,2)` | 交換**兩個**維度 | ❌ 不會 | ❌ 不需要 | ❌ 不變 |

```python
import torch
x = torch.arange(24).reshape(2, 3, 4)
print(x.is_contiguous())            # True

y = x.permute(1, 0, 2)              # 只改了「怎麼走記憶體」，資料沒動
print(y.is_contiguous())            # False   <- 變不連續了

# y.view(6, 4)                      # RuntimeError
print(y.reshape(6, 4).shape)        # (6,4)  自動幫你複製一份連續的
print(y.contiguous().view(6, 4).shape)   # 手動版，跟上面等價
```

**`permute` 和 `transpose` 的差別：**

```python
x = torch.randn(2, 3, 4)
x.transpose(1, 2).shape       # (2, 4, 3)   只能換兩個
x.permute(2, 0, 1).shape      # (4, 2, 3)   任意重排，要寫出「所有」維度
```

> ✅ **結論**：改形狀不確定時一律用 `reshape`；換順序時，只換兩維用 `transpose`
>（比較好讀），多維重排用 `permute`。**`permute` 之後絕對不要接 `view`。**

## 2. cat vs stack

| | 維度數 | 要求 |
|---|---|---|
| `torch.cat([a,b], dim=0)` | **不變** | 除了 `dim` 那一維，其他都要一樣 |
| `torch.stack([a,b], dim=0)` | **+1** | 所有 tensor 形狀必須**完全相同** |

```python
a = torch.zeros(2, 3)
b = torch.ones(2, 3)
torch.cat([a, b], dim=0).shape      # (4, 3)      2+2=4，還是 2 維
torch.cat([a, b], dim=1).shape      # (2, 6)
torch.stack([a, b], dim=0).shape    # (2, 2, 3)   多了一維，長度 = 幾個 tensor
torch.stack([a, b], dim=-1).shape   # (2, 3, 2)
```

**記法**：`cat` 是「接長」，`stack` 是「疊高」。

> DataLoader 預設就是用 `stack` 把單筆樣本疊成 batch ——
> 這也解釋了為什麼**樣本長度不一樣時會報錯**，需要自訂 `collate_fn`。

## 3. expand vs repeat vs repeat_interleave

| | 佔記憶體 | 可以寫入 | 限制 |
|---|---|---|---|
| `expand(4,3)` | ❌ 不佔（假裝有） | ❌ 不行 | 只能擴張長度為 **1** 的維度 |
| `repeat(4,1)` | ✅ 真的複製 | ✅ 可以 | 無限制 |
| `repeat_interleave(2)` | ✅ 複製 | ✅ | 每個元素各自重複 |

```python
x = torch.tensor([[1., 2., 3.]])       # (1, 3)
e, r = x.expand(4, 3), x.repeat(4, 1)
print(e.data_ptr() == x.data_ptr())    # True   <- 共享同一塊記憶體
print(r.data_ptr() == x.data_ptr())    # False  <- 真的複製了

a = torch.tensor([1, 2, 3])
a.repeat(2)                 # [1,2,3,1,2,3]   整組重複
a.repeat_interleave(2)      # [1,1,2,2,3,3]   每個元素重複
```

> ✅ 只是拿去做運算（唯讀）用 `expand` 省記憶體；需要修改結果才用 `repeat`。

## 4. squeeze vs unsqueeze vs None vs flatten

| 目的 | 寫法 | 備註 |
|---|---|---|
| 加一維 | `x.unsqueeze(0)` / `x[None]` | 完全等價，`[None]` 比較短 |
| 加在中間 | `x[:, None]` / `x.unsqueeze(1)` | |
| 刪掉長度 1 的維 | `x.squeeze(0)` | ★ **一定要指定 dim** |
| 攤平 | `x.flatten(1)` | 從 dim1 起攤平，保留 batch |

```python
x = torch.randn(1, 10)
x.squeeze().shape          # (10,)     <- batch=1 時把 batch 維也殺了！
x.squeeze(-1).shape        # (1, 10)   只動最後一維，安全
```

> 🔥 **`squeeze()` 不加參數是 bug 溫床**：平常 batch=32 沒事，
> 最後一個 batch 剛好剩 1 筆時就炸掉，而且錯誤訊息離現場很遠。

## 5. torch.tensor vs from_numpy vs as_tensor

| | 複製記憶體 | 共享（改一個影響另一個） |
|---|---|---|
| `torch.tensor(arr)` | ✅ 一定複製 | ❌ 獨立 |
| `torch.from_numpy(arr)` | ❌ 不複製 | ✅ **共享** |
| `torch.as_tensor(arr)` | 盡量不複製 | 通常共享 |

```python
import numpy as np
arr = np.array([1., 2., 3.], dtype=np.float32)
t1 = torch.from_numpy(arr)
t2 = torch.tensor(arr)
arr[0] = 999
print(t1[0], t2[0])        # tensor(999.)  tensor(1.)   <- t1 被連動了
```

> ✅ 不想被連動用 `torch.tensor`；追求效能且確定不會改原陣列，用 `from_numpy`。
> ⚠️ 兩者都會保留 NumPy 的 `float64`，記得先 `arr.astype(np.float32)`。

## 6. item vs detach vs cpu vs numpy

```python
loss = criterion(model(x), y)      # 一個在 GPU 上、帶著計算圖的純量 tensor
```

| 你想要 | 寫法 | 得到什麼 |
|---|---|---|
| 一個 Python 數字（記 log） | `loss.item()` | `float` |
| 還在 GPU 但不帶圖 | `loss.detach()` | tensor |
| 搬到 CPU | `loss.cpu()` | tensor |
| 轉成 NumPy | `loss.detach().cpu().numpy()` | ndarray |

```python
total += loss                # 抓住整張計算圖 -> 記憶體一路漲到 OOM
total += loss.item()         # 只是一個數字
total += loss.detach()       # 想留在 GPU 上累加時
```

> 🔥 `.item()` 只能用在「只有一個元素」的 tensor 上，多元素會報錯，要用 `.tolist()`。

## 7. detach vs no_grad vs requires_grad_(False) vs inference_mode

| 寫法 | 作用範圍 | 典型場景 |
|---|---|---|
| `x.detach()` | **單一 tensor** 的一條路 | GAN 訓練 D、SimSiam stop-grad、RL target |
| `with torch.no_grad():` | **整個區塊** | 驗證迴圈、手動更新參數 |
| `p.requires_grad_(False)` | **某些參數，永久** | 凍結骨幹、linear probe |
| `@torch.inference_mode()` | 整個函式，比 no_grad 更徹底 | 純推論 |

```python
# 情境 A：只想切斷「一條」路，其他路照常
feat = encoder(x)
loss_a = head_a(feat).mean()              # 這條會更新 encoder
loss_b = head_b(feat.detach()).mean()     # 這條不會
(loss_a + loss_b).backward()

# 情境 B：整段都不需要梯度
@torch.no_grad()
def evaluate(model, loader): ...

# 情境 C：某些參數永遠不訓練
for p in model.backbone.parameters():
    p.requires_grad_(False)
```

> ⚠️ `inference_mode()` 產生的 tensor **不能**再參與任何需要梯度的運算。只在最終部署時用。

## 8. clone vs detach vs copy_

| 寫法 | 新記憶體 | 還在計算圖上 |
|---|---|---|
| `y = x` | ❌ 同一個物件 | ✅ |
| `x.clone()` | ✅ | ✅ 梯度會流回 x |
| `x.detach()` | ❌ **共享記憶體** | ❌ |
| `x.clone().detach()` | ✅ | ❌ |

```python
x = torch.tensor([1., 2.], requires_grad=True)
a = x.detach()
a[0] = 99
print(x)        # tensor([99., 2.], requires_grad=True)   <- x 也變了！
```

> ✅ 要「完全獨立、不帶梯度」的副本，標準寫法是 `x.clone().detach()`。

## 9. nn.ReLU vs F.relu（模組 vs 函式）

PyTorch 大部分運算都有**兩個版本**：

| | `torch.nn.X`（大寫開頭） | `torch.nn.functional.x`（小寫） |
|---|---|---|
| 本質 | 一個**類別**，要先實例化 | 一個**函式**，直接呼叫 |
| 有沒有自己的參數 | 可以有（例如 Linear 的權重） | 沒有，參數要自己傳進去 |
| 放在哪 | `__init__` 裡建好，`forward` 裡用 | 直接寫在 `forward` 裡 |
| 能不能放進 Sequential | ✅ 可以 | ❌ 不行 |

```python
import torch.nn as nn
import torch.nn.functional as F

class M(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(10, 5)      # ★ 有權重，必須用 nn.（且要存成屬性）
        self.act = nn.ReLU()            # 沒權重，用 nn. 也可以
    def forward(self, x):
        x = self.fc(x)
        x = self.act(x)                 # 寫法 A
        x = F.relu(x)                   # 寫法 B，跟 A 完全等價
        return x
```

**判斷準則：**

| 這個運算 | 用哪個 |
|---|---|
| 有可訓練參數（Linear, Conv2d, BatchNorm, Embedding） | **必須** `nn.`，且存成 `self.xxx` |
| 有狀態但沒參數（Dropout —— train/eval 行為不同） | **建議** `nn.`（會跟著 `model.eval()` 自動切換） |
| 純函式（relu, softmax, cross_entropy） | 兩者皆可，看你要不要放進 `Sequential` |

> 🔥 **`F.dropout` 的陷阱**：它不知道 model 是 train 還是 eval，
> 要自己傳 `training=self.training`。用 `nn.Dropout` 就自動處理了。
> ```python
> x = F.dropout(x, p=0.5)                          # 危險：eval 時還在丟棄！
> x = F.dropout(x, p=0.5, training=self.training)  # 正確但囉唆
> self.drop = nn.Dropout(0.5); x = self.drop(x)    # 推薦
> ```

## 10. nn.Sequential vs nn.ModuleList vs Python list

| | 自動註冊參數 | 有自己的 forward | 用途 |
|---|---|---|---|
| `nn.Sequential([...])` | ✅ | ✅ 依序執行 | 線性堆疊，直接 `self.net(x)` |
| `nn.ModuleList([...])` | ✅ | ❌ 要自己寫迴圈 | 需要自訂流程（Transformer 堆層） |
| `[...]`（Python list） | ❌ **不會** | ❌ | 🔥 **絕對不要用** |

```python
class Bad(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = [nn.Linear(10, 10) for _ in range(3)]      # ❌

class Good(nn.Module):
    def __init__(self):
        super().__init__()
        self.layers = nn.ModuleList([nn.Linear(10, 10) for _ in range(3)])   # ✅

print(sum(p.numel() for p in Bad().parameters()))    # 0     <- 一個參數都抓不到！
print(sum(p.numel() for p in Good().parameters()))   # 330
```

> 🔥 用 Python list 的症狀：**程式跑得動、loss 也會降（其他層在學）、
> 但那幾層永遠是初始值**，而且 `model.cuda()` 也不會搬它們（會 device 錯誤）。
> **檢查方法**：印 `sum(p.numel() for p in model.parameters())`，跟你預期的比對。

**Sequential vs ModuleList 怎麼選：**

```python
# 單純一層接一層 -> Sequential
self.features = nn.Sequential(nn.Conv2d(3,32,3), nn.ReLU(), nn.MaxPool2d(2))
x = self.features(x)

# 需要在中間做別的事（傳 mask、存中間結果）-> ModuleList
self.layers = nn.ModuleList([EncoderLayer(d) for _ in range(6)])
for layer in self.layers:
    x = layer(x, mask)          # Sequential 沒辦法傳第二個參數
```

## 11. BatchNorm vs LayerNorm vs GroupNorm vs InstanceNorm

**四者都在做「把數值拉回 mean=0, std=1」，差別只在「對誰算平均」。**

以 `(B, C, H, W)` 為例：

| | 對哪些維度算統計量 | 統計量個數 | batch 小時 | 適用 |
|---|---|---|---|---|
| `BatchNorm2d(C)` | `(B, H, W)`，每個 channel 一組 | C 組 | ❌ **不穩** | CNN，batch >= 16 |
| `LayerNorm(...)` | `(C, H, W)`，每個樣本一組 | B 組 | ✅ 穩 | Transformer、NLP |
| `GroupNorm(g, C)` | 每個樣本、每組 channel | B×g 組 | ✅ 穩 | batch 很小的 CNN |
| `InstanceNorm2d(C)` | 每個樣本每個 channel 的 `(H,W)` | B×C 組 | ✅ 穩 | 風格轉換、GAN |

```python
x = torch.randn(4, 8, 16, 16)
nn.BatchNorm2d(8)(x).shape        # (4,8,16,16)  跨 batch 統計
nn.GroupNorm(4, 8)(x).shape       # 8 個 channel 分成 4 組
nn.InstanceNorm2d(8)(x).shape     # 每張圖每個 channel 各自算

y = torch.randn(2, 10, 512)       # (B, L, D) 序列資料
nn.LayerNorm(512)(y).shape        # 對最後一維（特徵維）正規化
```

**BatchNorm 的兩個關鍵特性（其他三個都沒有）：**

1. **訓練/測試行為不同** —— 訓練用當前 batch 統計量，測試用累積的 running stats。
   這就是為什麼**忘記 `model.eval()` 驗證結果會怪怪的**。
2. **batch 內樣本會互相影響** —— 所以 batch 太小（< 8）統計量極不穩定，
   而且 WGAN-GP 這種「逐樣本」的方法不能用 BN。

> ✅ **選擇流程**：CNN 且 batch >= 16 → BatchNorm；
> Transformer/序列 → LayerNorm；
> CNN 但 batch < 8（8GB 顯卡跑大模型時）→ GroupNorm。

## 12. CrossEntropyLoss vs NLLLoss vs BCEWithLogitsLoss vs BCELoss

| Loss | 輸入要什麼 | 標籤要什麼 | 用在 |
|---|---|---|---|
| `CrossEntropyLoss` | **原始 logits**（不要 softmax） | `int64`，值域 `0~C-1` | ★ 多類別分類 |
| `NLLLoss` | **已經 `log_softmax` 過的** | 同上 | 需要自己控制 softmax 時 |
| `BCEWithLogitsLoss` | **原始 logits**（不要 sigmoid） | `float`，0 或 1 | ★ 二分類 / 多標籤 |
| `BCELoss` | **已經 sigmoid 過的機率** | 同上 | ⚠️ 數值不穩，別用 |

```python
logits = torch.randn(4, 3)              # 4 筆、3 類的原始分數
labels = torch.tensor([0, 2, 1, 0])     # int64

# 這三種寫法完全等價
F.cross_entropy(logits, labels)
F.nll_loss(F.log_softmax(logits, dim=1), labels)
(-F.log_softmax(logits, 1)[torch.arange(4), labels]).mean()
```

> 🔥 **最常見的錯誤 #1**：在模型最後加了 `nn.Softmax` 又用 `CrossEntropyLoss`
> → 等於做了兩次 softmax，**loss 從 2.3 降到 2.1 就卡住**，準確率上不去。
>
> 🔥 **最常見的錯誤 #2**：用 `Sigmoid + BCELoss`。
> 當 sigmoid 輸出剛好是 0 或 1 時，`log(0) = -inf` → loss 變 nan。
> `BCEWithLogitsLoss` 內部用了數值穩定的公式，**永遠選它**。

## 13. Adam vs AdamW vs SGD

| | 自適應學習率 | weight decay 怎麼做 | 收斂速度 | 最終精度 |
|---|---|---|---|---|
| `SGD(momentum=0.9)` | ❌ | 加進梯度（= L2 正則） | 慢 | ★ 調好時最高 |
| `Adam` | ✅ | 加進梯度（**會被自適應縮放稀釋**） | ★ 快 | 中 |
| `AdamW` | ✅ | **直接從權重減**（解耦） | ★ 快 | ★ 高 |

**Adam 和 AdamW 的差別（就這一行）：**

```python
# Adam：把 wd 混進梯度，之後會被 Adam 的自適應項除掉 -> 正則效果不如預期
grad = grad + wd * param

# AdamW：更新完之後直接從權重上扣 -> 這才是 weight decay 原本的意思
param = param - lr * adam_step - lr * wd * param
```

```python
optim.SGD(model.parameters(), lr=0.1, momentum=0.9, weight_decay=5e-4, nesterov=True)
optim.Adam(model.parameters(), lr=1e-3)
optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.05)      # ★ 現代預設
```

| 場景 | 選誰 | 起始 lr |
|---|---|---|
| ★ 一般情況、快速實驗 | **AdamW** | 1e-3 |
| CNN 分類想衝最高分 | SGD + momentum + cosine | 0.1（batch 128） |
| Transformer | AdamW + warmup | 1e-4 ~ 3e-4 |
| GAN | Adam, `betas=(0.5, 0.999)` | 2e-4 |
| Fine-tune 預訓練模型 | AdamW | 1e-5 ~ 5e-5 |

> ⚠️ **`weight_decay` 的合理值差 100 倍**：SGD 用 `5e-4`，AdamW 用 `0.01~0.1`。
> 直接把 SGD 的數字搬到 AdamW 等於幾乎沒有正則化。

## 14. reduction 的三種值

```python
F.cross_entropy(logits, y, reduction="mean")   # 預設，回傳純量
F.cross_entropy(logits, y, reduction="sum")    # 回傳純量（總和）
F.cross_entropy(logits, y, reduction="none")   # ★ 回傳 (B,)，每筆一個
```

| | 回傳 | 什麼時候用 |
|---|---|---|
| `"mean"` | 純量 | ★ 99% 的情況 |
| `"sum"` | 純量 | VAE 的 ELBO（數學定義是加總） |
| `"none"` | 每個樣本一個 | 自己加權、找困難樣本、Focal Loss |

```python
# 用 none 找出模型最不會的 5 筆資料（超好用的除錯手段）
per_sample = F.cross_entropy(logits, y, reduction="none")     # (B,)
hard_idx = per_sample.topk(5).indices
print("最難的 5 筆:", y[hard_idx])
```

> ⚠️ **`sum` 和 `mean` 差一個 batch size 的倍數**，換用時 lr 要跟著調。
> VAE 的 loss 用 `sum` 是因為 ELBO 對每個維度加總，最後才手動除以 batch。

## 15. model.eval() vs torch.no_grad()

**這是新手最常混淆的一組。它們管的是完全不同的事，兩個都要寫。**

| | 管什麼 | 影響什麼 | 省記憶體嗎 |
|---|---|---|---|
| `model.eval()` | **層的行為** | Dropout 停止丟棄；BatchNorm 改用 running stats | ❌ |
| `torch.no_grad()` | **要不要建計算圖** | 不記錄運算歷史 | ✅ 省一半 |

```python
model.eval()                    # ① 切換層的行為
with torch.no_grad():           # ② 關閉梯度追蹤
    for x, y in val_loader:
        logits = model(x)
```

| 漏掉哪個 | 症狀 |
|---|---|
| 漏 `model.eval()` | 驗證準確率偏低，而且**每次跑結果都不一樣**（dropout 還在隨機） |
| 漏 `no_grad()` | 記憶體暴增甚至 OOM，速度慢一倍（但結果是對的） |
| 驗證完忘記 `model.train()` | 第二個 epoch 起 dropout/BN 失效，開始過擬合 |

## 16. max vs amax vs argmax vs topk

```python
x = torch.tensor([[1., 5., 3.], [9., 2., 7.]])
```

| 寫法 | 回傳 | 結果 |
|---|---|---|
| `x.max()` | 純量 | `9.` |
| `x.max(dim=1)` | **兩個東西** `(values, indices)` | `([5.,9.], [1,0])` |
| `x.amax(dim=1)` | 只有值 | `[5., 9.]` |
| `x.argmax(dim=1)` | 只有索引 | `[1, 0]` |
| `x.topk(2, dim=1)` | `(values, indices)`，前 k 大 | `([5,3],[9,7])`, `([1,2],[0,2])` |

```python
values, indices = x.max(dim=1)      # ★ 一定要接兩個變數，不然拿到的是 tuple
preds = logits.argmax(dim=1)        # ★ 分類任務取預測類別的標準寫法
```

> ⚠️ **這跟 NumPy 不同**：NumPy 的 `a.max(axis=1)` 只回傳值。
> PyTorch 帶 `dim` 時回傳 tuple，忘記解包就會出現
> `AttributeError: 'torch.return_types.max' object has no attribute ...`。

## 17. gather vs index_select vs 花式索引

**問題：從 `(N, C)` 的 logits，取出「每一列各自指定的那個欄位」。**

```python
logits = torch.tensor([[1., 5., 3.], [9., 2., 7.], [4., 4., 8.]])
labels = torch.tensor([1, 0, 2])
```

| 寫法 | 適用 | 結果 |
|---|---|---|
| `logits[torch.arange(3), labels]` | 簡單、好讀 | `[5., 9., 8.]` |
| `logits.gather(1, labels[:, None]).squeeze(1)` | 高維度時較通用 | 同上 |
| `torch.index_select(logits, 0, idx)` | 取**整列/整欄** | 不同用途 |

```python
# index_select 是「取出某幾個完整的列」，跟上面兩個不一樣
torch.index_select(logits, 0, torch.tensor([0, 2]))    # 取第 0、2 列 -> (2,3)
```

> ✅ **記法**：`gather` = 「每一列各挑一個」；`index_select` = 「挑整列」。
> DQN 取「實際採取的動作的 Q 值」就是 `gather` 的經典場景。

## 18. pandas loc vs iloc vs [] vs at

| 寫法 | 用什麼定位 | 切片端點 | 速度 |
|---|---|---|---|
| `df.loc[列標籤, 欄標籤]` | **標籤** | **含右端點** | 中 |
| `df.iloc[列位置, 欄位置]` | **整數位置** | 不含右端點 | 中 |
| `df["欄名"]` | 只能選欄 | — | 快 |
| `df.at[列, 欄]` | 標籤，**單一格** | — | ★ 最快 |
| `df.iat[i, j]` | 位置，單一格 | — | ★ 最快 |

```python
df = pd.read_csv("2330.csv", parse_dates=["Date"], index_col="Date")

df.loc["2020-01-01":"2020-01-31"]      # ★ 含 1/31
df.iloc[0:5]                            # ★ 不含第 5 列（跟 Python 切片一致）
df.loc[df["K"] > 80, ["K", "D"]]        # ★ 條件 + 選欄，最常用的組合
df.at["2020-01-02", "K"]                # 單一格，比 loc 快
```

**為什麼 `loc` 含右端點？** 因為標籤沒有「下一個」的概念 ——
你寫 `"2020-01-31"` 就是要到 1/31，總不能叫你寫「1/31 的下一天」。

> 🔥 **pandas 3.0 的鐵律**：所有**寫入**都要用 `.loc` / `.iloc` **一步完成**。
> ```python
> df["a"][0] = 9        # ❌ 靜默失效（Copy-on-Write），df 完全沒變
> df.loc[0, "a"] = 9    # ✅
> ```

## 19. pandas apply vs map vs 向量化 vs iterrows

**同一件事的四種寫法，速度差 1000 倍。**

```python
# 目標：把 K 欄除以 100
df["K"] / 100                                    # ① 向量化    ★ 最快
df["K"].map(lambda v: v / 100)                   # ② Series.map
df["K"].apply(lambda v: v / 100)                 # ③ Series.apply
df.apply(lambda r: r["K"] / 100, axis=1)         # ④ 逐列 apply   慢
[r["K"] / 100 for _, r in df.iterrows()]         # ⑤ iterrows   ★ 最慢
```

| 寫法 | 相對速度 | 什麼時候用 |
|---|---|---|
| 向量化 `df["a"] + df["b"]` | **1x（基準）** | ★ 永遠優先 |
| `Series.map(dict)` | ~5x 慢 | 類別對映（`{0:"跌", 1:"漲"}`） |
| `Series.apply(f)` | ~10x 慢 | 真的沒有向量化寫法時 |
| `df.apply(f, axis=1)` | ~100x 慢 | 需要跨欄複雜邏輯 |
| `df.iterrows()` | ~1000x 慢 | 🔥 **永遠不要用來做數值運算** |
| `df.itertuples()` | ~100x 慢 | 真的要逐列時用這個（比 iterrows 快 10 倍） |

```python
# 大部分「看起來需要 apply」的情況都能向量化
df.apply(lambda r: r["K"] - r["D"], axis=1)     # ❌ 慢
df["K"] - df["D"]                                # ✅ 一樣的結果，快 100 倍

df.apply(lambda r: 1 if r["K"] > 80 else 0, axis=1)    # ❌
(df["K"] > 80).astype(int)                              # ✅
np.where(df["K"] > 80, 1, 0)                            # ✅ 多條件用這個
```

> ⚠️ **【新版】`df.applymap` 在 pandas 3.0 已移除**，改用 `df.map`。

## 20. pandas merge vs join vs concat

| 函式 | 依據什麼對齊 | 像什麼 |
|---|---|---|
| `pd.concat([a,b], axis=0)` | 直接疊列 | SQL `UNION` |
| `pd.concat([a,b], axis=1)` | **索引** | 並排 |
| `pd.merge(a, b, on="key")` | **指定欄位** | ★ SQL `JOIN` |
| `a.join(b)` | **索引**（merge 的簡寫） | JOIN on index |

```python
pd.concat([df1, df2], axis=0, ignore_index=True)     # 疊列（取代已移除的 append）
pd.merge(left, right, on="Date", how="inner")        # inner/left/right/outer
pd.concat([d1, d2, d3], axis=1, join="inner")        # ★ 三檔股票對齊日期
```

**`how` 的四種：**

| `how` | 保留誰 |
|---|---|
| `"inner"` | ★ 只留兩邊都有的（三檔股票對齊日期用這個） |
| `"left"` | 左邊全留，右邊沒有的填 NaN |
| `"right"` | 反之 |
| `"outer"` | 兩邊聯集 |

## 21. groupby 的 agg vs transform vs apply

**這三個是 groupby 之後最常混淆的。差別在「回傳的形狀」。**

```python
df = pd.DataFrame({"g": ["a","a","b","b","b"], "v": [1, 3, 10, 20, 30]})
```

| 方法 | 回傳形狀 | 結果 |
|---|---|---|
| `.agg("mean")` | **每組一列**（縮小） | `a:2, b:20` → 2 列 |
| `.transform("mean")` | **跟原 df 一樣長**（廣播回去） | `[2,2,20,20,20]` → 5 列 |
| `.apply(f)` | 看 f 回傳什麼，最彈性也最慢 | — |

```python
df.groupby("g")["v"].agg("mean")
# g
# a     2.0
# b    20.0

df.groupby("g")["v"].transform("mean")
# 0     2.0
# 1     2.0
# 2    20.0
# 3    20.0
# 4    20.0     <- ★ 可以直接當新欄位貼回去

df["v_group_mean"] = df.groupby("g")["v"].transform("mean")     # ✅ 長度對得上
df["v_group_mean"] = df.groupby("g")["v"].agg("mean")           # ❌ 長度不對
```

> ✅ **記法**：想做成**新欄位**就用 `transform`；想做**摘要表**就用 `agg`。

**多欄位聚合的兩種寫法：**

```python
df.groupby("g").agg({"v": ["mean", "std"]})              # 欄名會變雙層，難用
df.groupby("g").agg(v_mean=("v","mean"), v_std=("v","std"))   # ★ 推薦，欄名乾淨
```

## 22. NumPy 的 copy vs view

| 操作 | 結果 | 改了會影響原陣列嗎 |
|---|---|---|
| `a[2:5]`（基本切片） | **view** | ✅ 會 |
| `a[[2,3,4]]`（花式索引） | **copy** | ❌ 不會 |
| `a[a > 0]`（布林遮罩） | **copy** | ❌ 不會 |
| `a.reshape(...)` | 通常 view | ✅ 會 |
| `a.ravel()` | 盡量 view | 可能會 |
| `a.flatten()` | **一定 copy** | ❌ 不會 |
| `a.T` / `transpose` | view | ✅ 會 |
| `a.copy()` | copy | ❌ 不會 |

```python
a = np.arange(10)
b = a[2:5]; b[0] = 999
print(a[2])              # 999   <- 被改了
print(b.base is a)       # True  <- 檢查是不是 view

a = np.arange(10)
c = a[[2,3,4]]; c[0] = -1
print(a[2])              # 2     <- 沒被影響
print(c.base is None)    # True  <- 獨立的
```

> **PyTorch 完全相同的規則。** 這解釋了為什麼有時候「改一個 tensor 會神秘地影響另一個」。
> 想要獨立副本就明確寫 `.copy()`（NumPy）或 `.clone()`（PyTorch）。

## 23. axis vs dim、keepdims vs keepdim

**同一件事，兩個函式庫用不同名字。這是最容易打錯的地方。**

| 概念 | NumPy | PyTorch |
|---|---|---|
| 沿哪個維度 | `axis=1` | `dim=1` |
| 保留維度 | `keepdims=True` | `keepdim=True`（**沒有 s**） |
| 取最大 | `a.max(axis=1)` → 只有值 | `x.max(dim=1)` → **(值, 索引)** |
| 只要值 | `a.max(axis=1)` | `x.amax(dim=1)` |
| 加一維 | `np.newaxis` / `None` | `unsqueeze` / `None` |
| 串接 | `np.concatenate` | `torch.cat` |
| 絕對值裁切 | `np.clip` | `torch.clamp` |
| 型別轉換 | `.astype(np.float32)` | `.float()` / `.to(torch.float32)` |

**`axis=k` / `dim=k` 的統一理解：把第 k 個維度「消掉」。**

```python
x = torch.arange(24.).reshape(2, 3, 4)
x.sum(dim=0).shape          # (3, 4)      第 0 維消失
x.sum(dim=1).shape          # (2, 4)      第 1 維消失
x.sum(dim=1, keepdim=True).shape   # (2, 1, 4)   保留成長度 1
```

> ★ **`keepdim` 什麼時候一定要加？** 當你之後要拿結果去跟原陣列做廣播運算時：
> ```python
> x - x.mean(dim=1)                    # ❌ (2,3,4) - (2,4)  廣播失敗
> x - x.mean(dim=1, keepdim=True)      # ✅ (2,3,4) - (2,1,4)
> ```
> softmax 的實作就是這個道理。

## 24. `*` vs `@` vs matmul vs einsum

| 寫法 | 做什麼 | 形狀要求 |
|---|---|---|
| `a * b` | **逐元素**相乘 | 相同或可廣播 |
| `a @ b` | ★ **矩陣乘法** | `(...,m,k) @ (...,k,n)` |
| `torch.matmul(a,b)` | 同 `@` | 同上 |
| `torch.mm(a,b)` | 矩陣乘法，**只限 2D** | `(m,k) @ (k,n)` |
| `torch.bmm(a,b)` | batch 矩陣乘法，**只限 3D** | `(b,m,k) @ (b,k,n)` |
| `torch.einsum(...)` | 任意維度、可讀性最好 | 自己指定 |
| `torch.dot(a,b)` | 內積，**只限 1D** | `(n,) · (n,)` |

```python
A = torch.randn(3, 4)
B = torch.randn(4, 5)
A @ B                    # (3,5)  矩陣乘法
# A * B                  # ❌ 形狀不合，逐元素乘要求形狀一樣

X = torch.randn(8, 3, 4)
W = torch.randn(4, 5)
X @ W                    # (8,3,5)  W 自動廣播到每個 batch

Y = torch.randn(8, 4, 5)
X @ Y                    # (8,3,5)  逐 batch 相乘
```

**什麼時候用 einsum：維度多到 `transpose` 寫不清楚的時候。**

```python
Q = torch.randn(2, 8, 10, 64)     # (B, heads, L, d)
K = torch.randn(2, 8, 10, 64)

s1 = Q @ K.transpose(-2, -1)                    # 寫法 A：短但要想一下
s2 = torch.einsum("bhqd,bhkd->bhqk", Q, K)      # 寫法 B：一眼看出每維的角色
print(torch.allclose(s1, s2))                   # True
```

**einsum 的讀法**：出現在輸入但**不在**輸出的下標 → 對它求和。

```
"bhqd,bhkd->bhqk"
  ↑ d 在兩邊輸入都有、輸出沒有 -> 對 d 求和（這就是內積）
```

> ✅ **結論**：`@` 最常用也最快；`einsum` 用在 4 維以上、要讓人看懂的地方。
> `mm`/`bmm` 是舊 API，維度限制死板，新程式碼一律用 `@`。

## 25. 三種存模型的方式

| 方式 | 存了什麼 | 讀回來需要 | 建議 |
|---|---|---|---|
| `torch.save(model.state_dict(), p)` | 只有權重（一個 dict） | 原始的模型類別定義 | ★★ **一律用這個** |
| `torch.save(model, p)` | 整個物件（pickle） | 完全相同的類別路徑 | ❌ 不要用 |
| `torch.jit.script(model).save(p)` | 權重 + 計算圖 | 不需要原始碼 | 部署時用 |

```python
# ★ 標準做法
torch.save(model.state_dict(), "m.pt")

model = MyModel(**same_args)               # 先建出一模一樣的結構
model.load_state_dict(torch.load("m.pt", map_location="cpu", weights_only=True))
model.to(device).eval()
```

**為什麼不要存整個 model？** 因為 pickle 記錄了「這個類別在哪個檔案的哪一行」，
你把資料夾改名、把類別搬到別的檔案、或換一台電腦，就讀不回來了。

**存 checkpoint（要能續訓）時還要存這些：**

```python
torch.save({
    "epoch": ep,
    "model": model.state_dict(),
    "optimizer": optimizer.state_dict(),     # ★ Adam 有動量狀態，不存的話續訓會抖一下
    "scheduler": scheduler.state_dict(),     # ★ 不然 lr 會跳回起點
    "best_metric": best,
    "config": asdict(cfg),                   # ★ 三個月後你會需要它
}, "ck.pt")
```

**`strict=True` vs `strict=False`：**

```python
model.load_state_dict(sd)                    # strict=True（預設）：鍵不完全吻合就報錯
missing, unexpected = model.load_state_dict(sd, strict=False)   # 容忍不吻合
print("模型有但檔案沒有:", missing)
print("檔案有但模型沒有:", unexpected)
```

> 🔥 **`strict=False` 的陷阱**：它會**安靜地**忽略不吻合的鍵。
> 如果你打錯前綴導致**一個權重都沒載到**，程式照常跑、不報錯、只是效果爛。
> **一定要把 `missing` / `unexpected` 印出來看。**

## 26. float16 vs bfloat16 vs float32

| | 總位元 | 指數位 | 尾數位 | 動態範圍 | 精度 |
|---|---|---|---|---|---|
| `float32` | 32 | 8 | 23 | 大 | 高 |
| `float16` | 16 | 5 | 10 | **小**（容易溢位） | 中 |
| `bfloat16` | 16 | **8**（同 fp32） | 7 | **大** | 低 |

**關鍵洞見**：bf16 犧牲精度換動態範圍，fp16 反過來。
深度學習**對動態範圍比對精度敏感**，所以 bf16 通常更好用。

```python
# fp16 需要 GradScaler 防止梯度下溢（梯度太小變成 0）
scaler = torch.amp.GradScaler("cuda")
with torch.autocast("cuda", dtype=torch.float16):
    loss = criterion(model(x), y)
scaler.scale(loss).backward()
scaler.step(optimizer); scaler.update()

# ★ bf16 不需要 GradScaler，程式碼乾淨很多
with torch.autocast("cuda", dtype=torch.bfloat16):
    loss = criterion(model(x), y)
loss.backward()
optimizer.step()
```

> ✅ **你的 RTX 4060 支援 bf16（我實測確認過），直接用 bf16。**
> 檢查指令：`torch.cuda.is_bf16_supported()`

## 27. DataLoader 的參數組合

## 附錄：五個「看起來一樣但結果不同」的陷阱總整理

```python
# ① x.to(device) 不會就地修改，model.to(device) 會
x.to(device)              # ❌ 沒作用
x = x.to(device)          # ✅
model.to(device)          # ✅ Module 是就地搬移

# ② out += y 會壞掉 autograd，out = out + y 不會
out += self.shortcut(x)   # ❌ RuntimeError: ...modified by an inplace operation
out = out + self.shortcut(x)   # ✅

# ③ 布林運算用 & | ~，不能用 and or not
df[(df.a > 0) & (df.b < 5)]    # ✅
df[df.a > 0 and df.b < 5]      # ❌ ValueError: truth value is ambiguous

# ④ Python 的 / 永遠是浮點數
(H + 2*p - k) / s + 1     # ❌ 得到 float，拿去當 shape 會報錯
(H + 2*p - k) // s + 1    # ✅

    if lst is None: lst = []
```
