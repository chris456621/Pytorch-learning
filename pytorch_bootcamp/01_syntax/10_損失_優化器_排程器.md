## §1 損失函數：選錯就全錯

### 分類

```python
import torch.nn as nn
import torch.nn.functional as F

# ★ 多類別分類（最常用）
criterion = nn.CrossEntropyLoss()
loss = criterion(logits, labels)
# logits: (B, C) 原始分數，★ 不要先過 softmax！
# labels: (B,)  int64，值域 0 ~ C-1
```

> 🔥 **三個致命錯誤：**
> 1. **先做 softmax 再丟進 CrossEntropyLoss** → 等於做了兩次 softmax，模型幾乎學不動
> 2. **labels 是 float 或 one-hot** → 型別錯誤（除非你要用 label smoothing 的軟標籤）
> 3. **labels 從 1 開始編號** → `IndexError` 或悄悄學錯

```python
# 二分類（★ 用這個，不要用 Sigmoid + BCELoss）
criterion = nn.BCEWithLogitsLoss()        # 內建 sigmoid，數值穩定
loss = criterion(logits.squeeze(-1), labels.float())   # ★ labels 要 float

# 類別不平衡
nn.CrossEntropyLoss(weight=torch.tensor([1.0, 5.0, 2.0]))   # 每類權重
nn.BCEWithLogitsLoss(pos_weight=torch.tensor([3.0]))        # 正樣本權重

# 標籤平滑（★ 幾乎免費的 +0.5~1%）
nn.CrossEntropyLoss(label_smoothing=0.1)

# 忽略某個標籤（padding token）
nn.CrossEntropyLoss(ignore_index=-100)
```

**序列任務的 shape 處理：**

```python
# logits: (B, L, C)，labels: (B, L)
loss = F.cross_entropy(logits.reshape(-1, C), labels.reshape(-1))
# 或用 PyTorch 支援的形式：logits (B, C, L)
loss = F.cross_entropy(logits.transpose(1, 2), labels)
```

### 迴歸

```python
nn.MSELoss()          # L2，對離群值敏感
nn.L1Loss()           # MAE，較耐離群值
nn.SmoothL1Loss()     # ★ Huber，兩者折衷（RL 的 DQN 常用）
nn.HuberLoss(delta=1.0)
```

> ⚠️ 迴歸最常見的 bug 是 shape 沒對齊（`(B,1)` vs `(B,)`）造成靜默廣播。
> **算 loss 前一定要 `assert pred.shape == target.shape`。**

### 其他你會用到的

```python
nn.KLDivLoss(reduction="batchmean")    # ★ 知識蒸餾（注意 input 要先 log_softmax）
nn.CosineEmbeddingLoss()               # 表徵相似度
nn.TripletMarginLoss(margin=1.0)       # 度量學習
nn.NLLLoss()                           # 配合 log_softmax（= CrossEntropy 拆開）
```

### reduction 參數

```python
F.cross_entropy(logits, y, reduction="mean")   # 預設，回傳純量
F.cross_entropy(logits, y, reduction="sum")
F.cross_entropy(logits, y, reduction="none")   # ★ 回傳每個樣本的 loss (B,)
# 用途：自己加權、找出 loss 最大的困難樣本
per_sample = F.cross_entropy(logits, y, reduction="none")
hard_idx = per_sample.topk(5).indices           # 找出最難的 5 筆來檢查
```

### 自訂 loss

```python
class FocalLoss(nn.Module):
    """對難分樣本加權，處理極度不平衡資料。"""
    def __init__(self, gamma=2.0, alpha=None):
        super().__init__()
        self.gamma, self.alpha = gamma, alpha

    def forward(self, logits, targets):
        ce = F.cross_entropy(logits, targets, weight=self.alpha, reduction="none")
        pt = torch.exp(-ce)                       # 預測正確類別的機率
        return ((1 - pt) ** self.gamma * ce).mean()
```

## §2 優化器

```python
import torch.optim as optim

optim.SGD(model.parameters(), lr=0.1, momentum=0.9,
          weight_decay=5e-4, nesterov=True)
optim.Adam(model.parameters(), lr=1e-3, betas=(0.9, 0.999), eps=1e-8)
optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.01)   # ★ 現代預設
optim.RMSprop(model.parameters(), lr=1e-3)
```

### 該用哪一個

| 場景 | 優化器 | 起始 lr |
|---|---|---|
| CNN 圖片分類（想衝最高分） | SGD + momentum 0.9 + cosine | 0.1（batch 128） |
| ★ 一般情況、快速實驗 | **AdamW** | 1e-3 |
| Transformer | AdamW + warmup | 1e-4 ~ 3e-4 |
| GAN | Adam, betas=(0.5, 0.999) | 2e-4 |
| Fine-tune 預訓練模型 | AdamW | 1e-5 ~ 5e-5 |
| RL | Adam | 1e-4 ~ 3e-4 |

> ★ **Adam vs AdamW**：Adam 的 `weight_decay` 是加進梯度（等於 L2 正則，
> 但會被自適應學習率縮放而失效）；AdamW 是直接從權重上減（解耦權重衰減），
> **這才是原本 weight decay 該有的行為**。所以現在一律用 AdamW。

### 參數分組（★ 常見技巧：bias 和 norm 不做 weight decay）

```python
decay, no_decay = [], []
for name, p in model.named_parameters():
    if not p.requires_grad:
        continue
    if p.ndim <= 1 or name.endswith(".bias"):      # bias、BN/LN 的權重
        no_decay.append(p)
    else:
        decay.append(p)

optimizer = optim.AdamW([
    {"params": decay,    "weight_decay": 0.05},
    {"params": no_decay, "weight_decay": 0.0},
], lr=1e-3)
```

### optimizer 的三個關鍵動作

```python
optimizer.zero_grad(set_to_none=True)   # 清梯度
loss.backward()                          # 算梯度
optimizer.step()                         # 更新參數

optimizer.param_groups[0]["lr"]          # ★ 讀當前學習率（記錄用）
optimizer.state_dict()                   # 存 checkpoint 要一起存（Adam 有動量狀態）
```

## §3 學習率排程 ★（免費的準確率提升）

**學習率是最重要的超參數。** 排程做對，同樣的模型常常能多 1~3%。

```python
from torch.optim import lr_scheduler

# ★ 首選：Cosine Annealing（簡單有效）
sched = lr_scheduler.CosineAnnealingLR(optimizer, T_max=EPOCHS, eta_min=1e-6)

# 階梯下降（經典 ResNet 用法）
sched = lr_scheduler.MultiStepLR(optimizer, milestones=[60, 120, 160], gamma=0.2)
sched = lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 依驗證指標自動降（不知道該何時降時很好用）
sched = lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", factor=0.5,
                                       patience=5, min_lr=1e-6)

# ★ OneCycle（單次訓練想快速拿到好結果就用它）
sched = lr_scheduler.OneCycleLR(optimizer, max_lr=1e-2,
                                steps_per_epoch=len(train_loader), epochs=EPOCHS)

# 指數衰減
sched = lr_scheduler.ExponentialLR(optimizer, gamma=0.95)
```

### 呼叫時機 ★ 錯了排程就失效

```python
# 大多數排程器：每個 epoch 結束呼叫一次
for epoch in range(EPOCHS):
    train_one_epoch(...)
    val_loss = validate(...)
    sched.step()                      # ★ 放在 optimizer.step() 之後

# ReduceLROnPlateau：要餵指標
    sched.step(val_loss)

# OneCycleLR / 有 warmup 的排程：★ 每個 batch 呼叫一次
for x, y in loader:
    optimizer.step()
    sched.step()                      # ← 在迴圈裡面
```

### Warmup + Cosine（Transformer 標配，一定要會）★

```python
import math

def build_warmup_cosine(optimizer, warmup_steps, total_steps, min_ratio=0.01):
    def fn(step):
        if step < warmup_steps:
            return step / max(1, warmup_steps)                  # 線性升溫
        p = (step - warmup_steps) / max(1, total_steps - warmup_steps)
        return min_ratio + (1 - min_ratio) * 0.5 * (1 + math.cos(math.pi * p))
    return lr_scheduler.LambdaLR(optimizer, fn)

total_steps = EPOCHS * len(train_loader)
sched = build_warmup_cosine(optimizer, warmup_steps=int(0.05 * total_steps),
                            total_steps=total_steps)
# ★ 這個要在每個 batch 後 sched.step()
```

> **為什麼 Transformer 需要 warmup？**
> 訓練初期參數是隨機的，Adam 的二階動量估計還不準，
> 一開始就用大 lr 會讓 LayerNorm 後的分布劇烈震盪，
> 常常直接發散成 nan。Warmup 讓模型先「暖身」再加速。

### 怎麼找初始學習率（LR Range Test）

```python
def lr_finder(model, loader, criterion, device, lr_min=1e-7, lr_max=1, n=100):
    """從極小 lr 指數上升，畫出 loss-lr 曲線。挑「下降最陡」那一段的 lr。"""
    opt = optim.AdamW(model.parameters(), lr=lr_min)
    gamma = (lr_max / lr_min) ** (1 / n)
    sched = lr_scheduler.ExponentialLR(opt, gamma)
    lrs, losses = [], []
    it = iter(loader)
    for i in range(n):
        try: x, y = next(it)
        except StopIteration:
            it = iter(loader); x, y = next(it)
        x, y = x.to(device), y.to(device)
        opt.zero_grad()
        loss = criterion(model(x), y)
        loss.backward(); opt.step(); sched.step()
        lrs.append(opt.param_groups[0]["lr"]); losses.append(loss.item())
        if loss.item() > 4 * min(losses):      # 爆炸了就停
            break
    return lrs, losses
# 畫出來：plt.plot(lrs, losses); plt.xscale("log")
```

## §4 正則化總覽

| 方法 | 怎麼加 | 效果 |
|---|---|---|
| Weight decay | `AdamW(weight_decay=0.01)` | ★ 幾乎一定要有 |
| Dropout | `nn.Dropout(0.2)` | 全連接層有效，CNN 上效果有限 |
| 資料增強 | transforms | ★ **投報率最高** |
| Early stopping | 監控 val loss | ★ 一定要有 |
| Label smoothing | `CrossEntropyLoss(label_smoothing=0.1)` | 便宜的小提升 |
| 梯度裁剪 | `clip_grad_norm_` | 防爆炸，RNN/Transformer 必備 |
| BatchNorm / LayerNorm | 加層 | 有正則化副作用 |
| Mixup / CutMix | 改資料 + 改 loss | 強但要調 |

```python
# Early stopping 的標準實作
class EarlyStopping:
    def __init__(self, patience=10, min_delta=0.0, mode="min"):
        self.patience, self.min_delta, self.mode = patience, min_delta, mode
        self.best = None
        self.counter = 0
        self.should_stop = False

    def __call__(self, metric):
        if self.best is None:
            self.best = metric
            return True                       # 是新的最佳
        improved = (metric < self.best - self.min_delta) if self.mode == "min" \
                   else (metric > self.best + self.min_delta)
        if improved:
            self.best, self.counter = metric, 0
            return True
        self.counter += 1
        if self.counter >= self.patience:
            self.should_stop = True
        return False
```

## §5 調參的正確順序（★ 別亂調）

1. **先確認資料對** —— sanity check、用眼睛看幾筆
2. **先讓模型過擬合一小撮資料** —— 拿 32 筆資料訓練到 loss 接近 0。
   做不到代表模型或訓練流程有 bug，調參沒有意義。
3. **調學習率** —— 影響最大，用 LR range test 或試 `[1e-2, 3e-3, 1e-3, 3e-4, 1e-4]`
4. **加排程** —— cosine 或 onecycle
5. **調 batch size** —— 通常越大越穩（記憶體允許下）
6. **加正則化** —— 觀察到過擬合才加
7. **調架構** —— 寬度、深度
8. **最後才調** —— optimizer 種類、betas、eps 這些

> 🔥 **第 2 步是最重要也最常被跳過的一步。**
> ```python
> # 把 30 行的 debug 流程濃縮成這樣
> tiny = Subset(train_ds, range(32))
> tiny_loader = DataLoader(tiny, batch_size=32)
> for ep in range(200):
>     loss = train_one_epoch(model, tiny_loader, ...)
> # loss 應該要降到接近 0。如果不會，就是有 bug，不要往下做。
> ```
